
## 1. What is React.js and why is it used?
React.js is a **declarative, component‑based JavaScript library** created and maintained by Facebook. It enables developers to build complex user interfaces by breaking them into small, reusable pieces called *components*. React abstracts away direct DOM manipulation and instead lets you describe **what the UI should look like** for a given state. When the state changes, React efficiently updates only the parts of the DOM that actually need to change, which leads to better performance and a smoother development experience. It is widely used because it promotes code reuse, improves maintainability, and works well with modern tooling and ecosystems.

## 2. What are the main features of React.js?
- **JSX** – a syntax extension that mixes HTML‑like markup with JavaScript, making UI code more readable.  
- **Virtual DOM** – an in‑memory representation of the real DOM that allows React to compute the minimal set of changes needed.  
- **Component‑Based Architecture** – UI is composed of isolated, reusable components that manage their own state and lifecycle.  
- **One‑Way Data Flow** – data flows from parent to child via *props*, which makes the data flow predictable and easier to debug.  
- **Hooks** – functions like `useState` and `useEffect that let functional components have state and side‑effects without writing class components.  
- **Rich Ecosystem** – a large collection of third‑party libraries, dev tools, and community resources.

## 3. What is JSX in React?
JSX (JavaScript XML) is a **syntax extension** that allows you to write markup that looks like HTML directly inside JavaScript. Under the hood, a build tool such as Babel transforms JSX into `React.createElement` calls, which produce plain JavaScript objects (React elements). JSX makes component code more expressive and easier to understand because the UI structure is written in a familiar, HTML‑like way while still allowing you to embed JavaScript expressions using curly braces (`{}`).

## 4. What is the difference between React and React DOM?
- **React** (`react` package) contains the core library: component definitions, state management, lifecycle methods, and the reconciler that works with the virtual DOM.  
- **React DOM** (`react-dom` package) provides the **renderer** that takes the virtual DOM tree generated by React and mounts it into the actual browser DOM (or other environments like `react-native`). In other words, React is the *logic* and React DOM is the *platform‑specific* glue.

## 5. What is a virtual DOM in React?
The virtual DOM is a **lightweight JavaScript object tree** that mirrors the structure of the real DOM. When a component’s state or props change, React creates a new virtual DOM tree, compares it with the previous one (a process called *reconciliation*), and calculates the smallest set of changes (patches). Those patches are then applied to the real DOM, which avoids costly full‑page re‑renders and results in smoother UI updates.

## 6. How does React's virtual DOM work?
1. **Render Phase** – React calls each component’s render function (or functional component body) to produce a new virtual DOM tree.  
2. **Diffing Phase** – React walks the old and new trees simultaneously, comparing nodes by type and key.  
3. **Reconciliation** – For each node that changed, React creates a *patch* describing how to update the real DOM (e.g., change text, add/remove an element).  
4. **Commit Phase** – The patches are applied to the real DOM in a batch, minimizing layout thrashing and repaint costs.

## 7. What are the advantages of using React?
- **Performance** – The virtual DOM reduces unnecessary DOM operations.  
- **Reusability** – Components can be shared across projects, reducing duplication.  
- **Maintainability** – Clear separation of concerns and a predictable data flow make code easier to reason about.  
- **Ecosystem** – Rich set of libraries for routing, state management, testing, etc.  
- **Developer Experience** – Tools like React DevTools, hot reloading, and a strong community accelerate development.

## 8. What is declarative programming in React?
Declarative programming means you **describe *what* the UI should look like** for a given state, rather than **how** to manipulate the DOM step‑by‑step. In React, you write JSX that reflects the UI at any point in time. When the state changes, React automatically re‑evaluates the JSX and updates the DOM accordingly, freeing you from manual DOM APIs.

## 9. What is component‑based architecture in React?
A component‑based architecture treats each UI piece as an **independent, self‑contained unit** (a component). Each component encapsulates its own markup, style, and behavior, and can manage its own state. Components can be **nested** to build complex UIs, and they can be **reused** across different parts of an application or even across projects.

## 10. How does React handle data flow?
React enforces **one‑way (unidirectional) data flow**:  
- **Parent → Child**: Data is passed down via *props*.  
- **Child → Parent**: Children communicate upward by invoking callback functions passed as props.  
- **Global State**: For data that must be shared across many components, React provides Context or external state libraries (Redux, MobX). This predictable flow makes debugging easier because data changes have a single source of truth.

## 11. What is a React component?
A React component is a **reusable building block** that returns a piece of UI. It can be defined as:  
- **Function Component** – a plain JavaScript function that returns JSX.  
- **Class Component** – an ES6 class extending `React.Component` with a `render` method.  
Both receive *props* as input and may maintain *state* internally.

## 12. What are the different types of React components?
- **Functional Components** – lightweight functions that can use Hooks for state and side effects.  
- **Class Components** – older style using `this.state` and lifecycle methods.  
- **Pure Components** – class components that implement a shallow prop comparison (`React.PureComponent`) to avoid unnecessary re‑renders.  
- **Higher‑Order Components (HOCs)** – functions that take a component and return an enhanced component (used for cross‑cutting concerns).

            return `Hi!! ${name} `;
        }

        function greet_name(greeting,message,name){
              console.log(`${greeting(name)} ${message}`);
        }

        greet_name(greet,'Welcome To GeeksForGeeks','JavaScript');


## 13. What is the difference between functional and class components?
- **Syntax & Boilerplate** – Functional components are simple functions; class components require a class definition, constructor, and `this` binding.  
- **State & Lifecycle** – Historically, only class components could have state and lifecycle methods. Since React 16.8, Hooks give functional components the same capabilities, making them the preferred style.  
- **Performance** – Functional components avoid the overhead of `this` and are generally easier for the compiler to optimize.

## 14. How do you create a functional component in React?
```jsx
function Greeting({ name }) {
  return <h1>Hello, {name}!</h1>;
}
```
You can also use an arrow function:
```jsx
const Greeting = ({ name }) => <h1>Hello, {name}!</h1>;
```
Functional components receive `props` as their argument and return JSX.

## 15. How do you create a class component in React?
```jsx
class Greeting extends React.Component {
  render() {
    return <h1>Hello, {this.props.name}!</h1>;
  }
}
```
Class components must extend `React.Component` and implement a `render` method that returns JSX. They can also define lifecycle methods and maintain internal state via `this.state`.

## 16. What are React hooks?
Hooks are **functions** that let you “hook into” React’s stateful features from functional components. The most common hooks are:
- `useState` – adds local state.  
- `useEffect` – runs side effects after render.  
- `useContext` – consumes a context value.  
- `useReducer`, `useCallback`, `useMemo`, `useRef`, etc.  
Hooks enable functional components to be as powerful as class components while keeping the code more concise.

## 17. When should you use functional components vs class components?
Prefer **functional components** for all new code because they are simpler, support Hooks, and avoid the verbosity of classes. Use **class components** only when you need to work with legacy code that still relies on lifecycle methods not yet refactored to Hooks.

## 18. What is the difference between presentational and container components?
- **Presentational (UI) Components** – focus solely on how things look. They receive data via props and rarely have their own state.  
- **Container (Smart) Components** – handle data fetching, state management, and business logic. They pass data down to presentational components. This separation encourages a clean architecture and easier testing.

## 19. How do you compose components in React?
Composition is achieved by **nesting components** inside each other, passing data via props, or using the special `children` prop. Example:
```jsx
function Card({ title, children }) {
  return (
    <div className="card">
      <h2>{title}</h2>
      {children}
    </div>
  );
}
```
You can then use `<Card>` to wrap any other component or markup.

## 20. What are component lifecycle methods?
Lifecycle methods exist only in **class components** and describe phases of a component’s existence:
- **Mounting**: `constructor`, `componentDidMount` (after first render).  
- **Updating**: `shouldComponentUpdate`, `componentDidUpdate`.  
- **Unmounting**: `componentWillUnmount`.  
- **Error Handling**: `componentDidCatch`.  
In functional components, the same concepts are expressed with `useEffect` (mount & unmount) and other Hooks.

## 21. What is JSX and how does it work?
JSX is a **syntax sugar** that allows you to write HTML‑like code inside JavaScript. Babel transpiles JSX into `React.createElement` calls, which produce plain JavaScript objects (React elements). These objects describe the type of element, its props, and its children, which React later uses to build the virtual DOM.

## 22. How does JSX get converted to JavaScript?
During the build step, Babel applies the `@babel/preset-react` plugin, which transforms:
```jsx
<div className="msg">Hello</div>
```
into:
```js
React.createElement('div', { className: 'msg' }, 'Hello');
```
This conversion enables the browser to execute the code, as browsers do not understand JSX natively.

## 23. What are the rules of JSX?
- **Single Root Element** – each JSX expression must return one parent element (use fragments `<>...</>` if needed).  
- **CamelCase Props** – HTML attributes become camelCase (`className`, `htmlFor`).  
- **JavaScript Expressions** – embed with `{}`.  
- **Self‑Closing Tags** – tags without children must be closed (`<img />`).  
- **Comments** – placed inside `{/* comment */}`.

## 24. How do you embed JavaScript expressions in JSX?
Wrap the expression in curly braces:
```jsx
<p>{user.name} is {user.age} years old.</p>
```
You can embed any valid JavaScript expression, including ternary operators, function calls, or variable references.

## 25. How do you handle conditional rendering in JSX?
Common patterns:
- **Ternary Operator**: `{condition ? <A /> : <B />}`  
- **Logical AND**: `{condition && <A />}` (renders `<A />` only when `condition` is truthy)  
- **Conditional Functions**: Write a helper function that returns JSX based on complex logic.

## 26. How do you render lists in JSX?
Use `Array.map` to transform each item into a component, and **provide a unique `key`** prop:
```jsx
<ul>
  {items.map(item => (
    <li key={item.id}>{item.name}</li>
  ))}
</ul>
```
The `key` helps React identify which items have changed, added, or removed.

## 27. How do you handle attributes in JSX?
Attributes follow **camelCase** naming (e.g., `onClick`, `tabIndex`). Boolean attributes can be written as `{true}` or omitted. For custom data attributes, use `data-` prefix (`data-id="123"`).

## 28. What are JSX fragments?
Fragments let you return **multiple sibling elements** without adding an extra DOM node:
```jsx
<>
  <Header />
  <Content />
</>
```
They are useful when a component must render several elements but you don’t want an unnecessary wrapper `<div>`.

## 29. How do you handle comments in JSX?
Place comments inside curly braces:
```jsx
{/* This is a JSX comment */}
```
Regular JavaScript `//` or `/* */` comments outside of JSX are also allowed.

## 30. What are the limitations of JSX?
- **Requires a Build Step** – browsers cannot parse JSX directly.  
- **Not Full HTML** – some HTML attributes have different names (`className` vs `class`).  
- **Limited to Expressions** – you cannot use statements (e.g., `if` without a ternary) directly inside JSX; you must wrap them in a function or use conditional operators.

## 31. What is props in React?
*Props* (short for **properties**) are **read‑only inputs** passed from a parent component to a child component. They allow data to flow down the component tree. A component cannot modify its own props; any change must be communicated back to the parent via callbacks.

## 32. What is state in React?
*State* is **mutable data** that lives inside a component. Changing state triggers a re‑render of that component (and its children). In class components, state is stored in `this.state`; in functional components, the `useState` hook provides a state variable and a setter function.

## 33. What is the difference between props and state?
- **Props**: Passed from parent → child, immutable within the child.  
- **State**: Owned by the component itself, can be updated via `setState` or `useState`.  
Props are used for configuration, while state holds data that changes over time.

## 34. How do you pass props to components?
```jsx
<Child title="Welcome" count={5} />
```
Inside `Child`, you access them via `props.title` (class) or directly as function arguments (`{ title, count }`).

## 35. How do you handle default props?
For functional components, you can use default parameters:
```jsx
function Button({ label = 'Click me' }) { … }
```
For class components, define a static `defaultProps` object:
```jsx
Button.defaultProps = { label: 'Click me' };
```

## 36. How do you validate props in React?
Use the **PropTypes** library:
```jsx
import PropTypes from 'prop-types';
Button.propTypes = {
  label: PropTypes.string.isRequired,
  onClick: PropTypes.func,
};
```
In TypeScript projects, you can define an interface for props, which provides compile‑time validation.

## 37. How do you update state in React?
- **Class Component**: `this.setState(prev => ({ count: prev.count + 1 }));`  
- **Functional Component**: `setCount(prev => prev + 1);`  
Both methods schedule a re‑render with the new state.

## 38. What is immutable state in React?
State should be treated as **immutable** – you never modify the existing object/array directly. Instead, create a new copy (using spread operator, `Array.map`, `Object.assign`, etc.) and set that as the new state. This allows React to detect changes efficiently via shallow comparison.

## 39. How do you lift state up in React?
When two sibling components need to share data, move the state to their **closest common ancestor**. The ancestor holds the state and passes it down as props, while providing callbacks to children to update the state. This pattern keeps a single source of truth.

## 40. What are controlled and uncontrolled components?
- **Controlled**: Form inputs whose value is driven by React state (`value={state}`) and updated via `onChange`. The component fully controls the input.  
- **Uncontrolled**: Inputs manage their own internal state; you retrieve their value using a ref (`ref.current.value`). Useful for simple forms or when you need to integrate with non‑React libraries.

## 41. What are React hooks?
Hooks are **functions** that let you use React features (state, lifecycle, context) inside functional components. They follow naming conventions (`useXxx`) and must be called at the top level of a component (not inside loops or conditionals) to preserve the order of Hook calls.

## 42. What is the `useState` hook?
`useState` adds **local state** to a functional component:
```jsx
const [count, setCount] = useState(0);
```
`count` holds the current value, and `setCount` updates it, causing a re‑render.

## 43. What is the `useEffect` hook?
`useEffect` runs **side effects** (e.g., data fetching, subscriptions) after the component renders. It accepts a function and an optional dependency array:
```jsx
useEffect(() => {
  // effect code
  return () => { /* cleanup */ };
}, [dep1, dep2]);
```
If the dependency array is empty, the effect runs only once (on mount).

## 44. What is the `useContext` hook?
`useContext` lets a component **consume a context value** without needing a `<Context.Consumer>` wrapper:
```jsx
const theme = useContext(ThemeContext);
```
It subscribes the component to context changes, causing a re‑render when the context value updates.

## 45. What is the `useReducer` hook?
`useReducer` provides an **alternative to `useState`** for complex state logic. It works like Redux reducers:
```jsx
const [state, dispatch] = useReducer(reducer, initialState);
```
You dispatch actions (`dispatch({ type: 'increment' })`) and the reducer returns the new state.

## 46. What is the `useCallback` hook?
`useCallback` memoizes a **function reference** so that it only changes when its dependencies change:
```jsx
const handleClick = useCallback(() => { … }, [id]);
```
Useful when passing callbacks to child components that rely on reference equality (e.g., `React.memo`).

## 47. What is the `useMemo` hook?
`useMemo` memoizes a **computed value**:
```jsx
const filtered = useMemo(() => items.filter(i => i.active), [items]);
```
It recomputes only when dependencies change, preventing expensive calculations on every render.

## 48. What is the `useRef` hook?
`useRef` returns a **mutable ref object** (`{ current: … }`) that persists across renders. Common uses:
- Accessing a DOM element (`ref={inputRef}`)  
- Storing mutable values that don’t trigger re‑renders (e.g., timers).

## 49. What is the `useLayoutEffect` hook?
`useLayoutEffect` runs **synchronously after DOM mutations** but before the browser paints. It is useful for measuring layout (e.g., getting element dimensions) and performing DOM mutations that must happen before the user sees the UI. It blocks painting, so use it sparingly.

## 50. What are custom hooks in React?
Custom hooks are **reusable functions** that encapsulate common Hook logic. They follow the same rules as built‑in Hooks and can call other Hooks. Example:
```jsx
function useFetch(url) {
  const [data, setData] = useState(null);
  useEffect(() => {
    fetch(url).then(r => r.json()).then(setData);
  }, [url]);
  return data;
}
```
Custom hooks promote code reuse and separation of concerns.

## 51. How do you manage state in React applications?
- **Local State**: `useState` or `useReducer` inside components.  
- **Global State**: Context API for simple cases; external libraries like **Redux**, **MobX**, **Recoil**, or **Zustand** for larger apps.  
- **Server State**: Libraries such as **React Query** or **Apollo Client** handle data fetching, caching, and synchronization with the server.

## 52. What is the Context API in React?
The Context API provides a way to **share values** (e.g., theme, user, locale) across the component tree without passing props at every level. You create a context with `React.createContext`, provide a value with `<Provider>`, and consume it with `useContext` or `<Consumer>`.

## 53. How do you use React Context for state management?
```jsx
const ThemeContext = React.createContext('light');

function App() {
  const [theme, setTheme] = useState('light');
  return (
    <ThemeContext.Provider value={{ theme, setTheme }}>
      <Toolbar />
    </ThemeContext.Provider>
  );
}
```
Any descendant can read or update the theme via `useContext(ThemeContext)`.

## 54. What is Redux and how does it work with React?
Redux is a **predictable state container** that stores the entire application state in a single immutable store. State updates happen via **pure reducer functions** that receive the current state and an action, returning a new state. React integrates with Redux through the `react-redux` library, which provides `<Provider>` to make the store available and hooks (`useSelector`, `useDispatch`) to read state and dispatch actions.

## 55. What is MobX and how does it work with React?
MobX uses **observable data structures** (objects, arrays) that automatically track which components read them. When an observable changes, any component that observed it re‑renders. Integration is done via the `mobx-react` package, typically using the `observer` higher‑order component or `useObserver` hook.

## 56. What is the difference between local state and global state?
- **Local State**: Scoped to a single component; managed with `useState` or `useReducer`.  
- **Global State**: Shared across many components; stored in a central place (Context, Redux, etc.) and accessed via hooks or HOCs. Global state is useful for authentication, theme, or data that many parts of the UI need.

## 57. How do you handle complex state management in React?
Combine **reducers** (`useReducer` or Redux) with **Context** to provide the dispatch function globally. Split the state into logical slices, use middleware (e.g., Redux Thunk or Saga) for async logic, and keep side‑effects separate from pure reducers.

## 58. What are the best practices for state management in React?
- Keep state **as close to where it is used** as possible.  
- Normalize data (store entities by ID).  
- Use **immutable updates** to enable shallow comparison.  
- Prefer **Redux Toolkit** or **React Query** for boilerplate reduction.  
- Avoid over‑centralizing state; not everything belongs in a global store.

## 59. How do you optimize state management performance?
- **Memoize selectors** with `reselect` to avoid recomputing derived data.  
- Use **React.memo** for pure components.  
- Split reducers and load them lazily (code‑splitting).  
- Batch state updates (React does this automatically in event handlers).  
- Use **immer** or the built‑in `createSlice` from Redux Toolkit for concise immutable updates.

## 60. What are the alternatives to Redux for state management?
- **MobX** – observable‑based, less boilerplate.  
- **Recoil** – atom‑based state with fine‑grained subscriptions.  
- **Zustand** – minimalistic store with hooks.  
- **React Query** – focuses on server state (caching, background refetch).  
- **Context + useReducer** – simple global state without external libraries.

## 61. How do you handle events in React?
Attach event handlers as **props** using camelCase names (`onClick`, `onChange`). React normalizes events into a **SyntheticEvent** object that works consistently across browsers. Example:
```jsx
<button onClick={handleClick}>Click</button>
```

## 62. What is event pooling in React?
React reuses **SyntheticEvent** objects from a pool for performance. After the event callback finishes, the event’s properties are cleared. If you need to access the event asynchronously, call `event.persist()` to remove it from the pool.

## 63. How do you pass arguments to event handlers?
Wrap the handler in an arrow function or use `bind`:
```jsx
<button onClick={() => handleDelete(id)}>Delete</button>
```
This creates a new function on each render, which is fine for most cases; for performance‑critical lists, you can memoize the handler with `useCallback`.

## 64. What are synthetic events in React?
Synthetic events are **cross‑browser wrappers** around native browser events. They provide a consistent API (e.g., `event.preventDefault()`) and support event pooling. They behave like native events but are managed by React’s event system.

## 65. How do you prevent default behavior in React events?
Call `event.preventDefault()` inside the event handler:
```jsx
<form onSubmit={e => { e.preventDefault(); /* custom logic */ }}>
```

## 66. How do you stop event propagation in React?
Use `event.stopPropagation()` to prevent the event from bubbling up to parent elements.

## 67. How do you handle keyboard events in React?
Attach `onKeyDown`, `onKeyUp`, or `onKeyPress` to an element and inspect `event.key` or `event.code`:
```jsx
<input onKeyDown={e => { if (e.key === 'Enter') submit(); }} />
```

## 68. How do you handle form events in React?
- Use `onSubmit` on the `<form>` element and call `event.preventDefault()` to stop the default page reload.  
- Manage each input’s value with **controlled components** (`value` + `onChange`).  
- Optionally use libraries like **Formik** or **React Hook Form** for complex validation.

## 69. How do you handle mouse events in React?
Attach handlers such as `onMouseEnter`, `onMouseLeave`, `onMouseDown`, `onMouseUp`, and `onMouseMove`. Example:
```jsx
<div onMouseEnter={handleEnter} onMouseLeave={handleLeave}>Hover me</div>
```

## 70. What are the best practices for event handling in React?
- **Debounce** expensive handlers (e.g., scroll, resize).  
- **Clean up** listeners added outside React (e.g., `window.addEventListener`) in a `useEffect` cleanup function.  
- Use **event delegation** when appropriate.  
- Keep handlers **pure** and avoid side effects that could cause memory leaks.

## 71. How do you handle forms in React?
Prefer **controlled components**: each input’s value is stored in component state and updated via `onChange`. On submit, gather the state and send it to the server. For large forms, use a library (Formik, React Hook Form) to manage state, validation, and error handling.

## 72. What are controlled components in React forms?
Inputs whose **value** is bound to a state variable and updated via `onChange`. Example:
```jsx
const [email, setEmail] = useState('');
<input type="email" value={email} onChange={e => setEmail(e.target.value)} />
```
The component fully controls the input’s value.

## 73. What are uncontrolled components in React forms?
Inputs that **manage their own internal state**. You retrieve their value using a **ref**:
```jsx
const emailRef = useRef();
<input type="email" ref={emailRef} />
// later: const email = emailRef.current.value;
```
Useful for simple forms or when integrating with non‑React libraries.

## 74. How do you handle form validation in React?
- **Schema‑based validation** with libraries like **Yup** or **Zod**.  
- **React Hook Form** or **Formik** integrate validation schemas and provide error messages.  
- Validate on **blur**, **change**, or **submit** depending on UX requirements.  
- Show user‑friendly error messages and highlight invalid fields.

## 75. How do you handle form submission in React?
```jsx
function handleSubmit(e) {
  e.preventDefault();
  // gather data from state or refs
  // send to API
}
<form onSubmit={handleSubmit}>…</form>
```
Prevent the default page reload, validate data, then perform the async request.

## 76. What is the difference between controlled and uncontrolled components?
Controlled components give React **full control** over the input’s value, enabling instant validation and UI synchronization. Uncontrolled components let the **DOM manage** the value, which can be simpler but offers less immediate feedback and harder state synchronization.

## 77. How do you handle multiple input fields in React forms?
Maintain a **single state object** representing the form:
```jsx
const [form, setForm] = useState({ name: '', email: '' });
const handleChange = e => {
  const { name, value } = e.target;
  setForm(prev => ({ ...prev, [name]: value }));
};
```
Each input uses `name` attribute to map to the corresponding state key.

## 78. How do you handle file uploads in React forms?
Use an `<input type="file">` (usually uncontrolled) and read the selected files via `e.target.files` or a ref. Then create a `FormData` object and send it with `fetch` or `axios`:
```jsx
const data = new FormData();
data.append('file', file);
await fetch('/upload', { method: 'POST', body: data });
```

## 79. How do you use form libraries with React?
- **Formik**: Provides `<Formik>` component, `useFormik` hook, and handles state, validation, and submission.  
- **React Hook Form**: Registers inputs via `register`, offers fast performance by avoiding re‑renders on each keystroke, and integrates with validation schemas.  
Both libraries reduce boilerplate and improve scalability for large forms.

## 80. What are the best practices for form handling in React?
- Use **controlled components** for simple forms; switch to a library for complex validation.  
- Validate **on the client** before sending data to the server.  
- Show **clear error messages** and use ARIA attributes for accessibility.  
- Debounce expensive validation if needed.  
- Reset form state after successful submission.

## 81. What are React component lifecycle methods?
- **Mounting**: `constructor`, `componentDidMount` – runs after the component is inserted into the DOM.  
- **Updating**: `shouldComponentUpdate`, `componentDidUpdate` – called when props or state change.  
- **Unmounting**: `componentWillUnmount` – cleanup before removal.  
- **Error Handling**: `componentDidCatch` – catches errors in child components.  
Functional components use `useEffect` to emulate these phases.

## 82. What is the mounting phase in React lifecycle?
During mounting, React creates the component instance, calls the **constructor** (if present), renders the JSX, and finally invokes **componentDidMount** (or the `useEffect` with empty dependency array) after the component is attached to the DOM. This is the ideal place for data fetching, subscriptions, or DOM measurements.

## 83. What is the updating phase in React lifecycle?
When a component receives new props or its state changes, React may call **shouldComponentUpdate** (to decide if a re‑render is needed), then **render**, followed by **componentDidUpdate** after the DOM updates. In functional components, `useEffect` without an empty dependency array runs after each render, serving a similar purpose.

## 84. What is the unmounting phase in React lifecycle?
Just before a component is removed from the DOM, **componentWillUnmount** is called (class) or the cleanup function returned from `useEffect` runs (functional). This is where you clean up timers, subscriptions, or any external resources.

## 85. What is the `componentDidMount` method?
`componentDidMount` runs **once** after the component is rendered and attached to the DOM. Common uses include:
- Fetching data from an API.  
- Setting up subscriptions (e.g., WebSocket, event listeners).  
- Measuring DOM nodes.

## 86. What is the `componentDidUpdate` method?
`componentDidUpdate(prevProps, prevState)` runs after the component updates and the DOM reflects the changes. It receives previous props and state, allowing you to compare and react to changes (e.g., fetch new data when a prop changes). Be careful to avoid infinite loops by conditionally performing actions.

## 87. What is the `componentWillUnmount` method?
`componentWillUnmount` is invoked **right before** a component is destroyed. It’s the place to:
- Remove event listeners.  
- Cancel network requests.  
- Clear timers (`clearTimeout`, `clearInterval`).  
- Unsubscribe from observables.

## 88. What is the `shouldComponentUpdate` method?
`shouldComponentUpdate(nextProps, nextState)` returns a boolean indicating whether React should re‑render the component. Returning `false` skips rendering, which can improve performance for pure components. In functional components, you achieve similar behavior with `React.memo`.

## 89. What is the `getSnapshotBeforeUpdate` method?
Called **right before** the DOM is updated, after `render`. It can capture information (e.g., scroll position) that you want to use in `componentDidUpdate`. The value returned from this method is passed as the third argument to `componentDidUpdate`.

## 90. How do lifecycle methods relate to React hooks?
- **Mount** → `useEffect(() => { … }, [])` (runs once).  
- **Update** → `useEffect(() => { … })` without dependency array (runs after every render).  
- **Unmount** → Return a cleanup function from `useEffect`.  
Hooks provide a unified API that works for both mounting and unmounting phases.

## 91. What is conditional rendering in React?
Conditional rendering means **showing or hiding** parts of the UI based on some condition (state, props, or derived values). It can be implemented with ternary operators, logical `&&`, `if` statements inside a render function, or separate helper functions.

## 92. How do you implement conditional rendering with if statements?
Inside the component’s body, you can use regular `if` statements to decide what JSX to return:
```jsx

  if (isLoading) return <Spinner />;
  return <Content />;
}
```
This keeps the JSX clean and readable.

## 93. How do you implement conditional rendering with ternary operators?
```jsx

```
The ternary is concise and works well for simple two‑branch conditions.

## 94. How do you implement conditional rendering with logical AND operator?
```jsx

```
If `error` is truthy, `<ErrorMessage>` renders; otherwise nothing is rendered.

## 95. How do you implement conditional rendering with switch statements?
Create a helper function that returns JSX based on a value:
```jsx

  switch (view) {
    case 'home': return <Home />;
    case 'profile': return <Profile />;
    default: return <NotFound />;
  }
}
```
Then call `{renderView(currentView)}` in the component.

## 96. How do you prevent component rendering in React?
- Return `null` from the component to render nothing.  
- Use `shouldComponentUpdate` (class) or wrap the component with `React.memo` (functional) and provide a custom comparison function that returns `false` when you want to skip rendering.

## 97. How do you handle conditional rendering with multiple conditions?
Combine logical operators or nest ternaries, but keep readability:
```jsx
{isLoading ? (
  <Spinner />
) : hasError ? (
  <ErrorMessage />
) : (
  <DataDisplay />
)}
```
Alternatively, extract the logic into a separate function.

## 98. What are the best practices for conditional rendering in React?
- Keep conditions **simple** and **readable**.  
- Prefer **early returns** to avoid deep nesting.  
- Use **null** instead of empty strings for “no render”.  
- Extract complex conditions into **helper functions** or separate components.

## 99. How do you optimize conditional rendering performance?
- **Memoize** expensive calculations with `useMemo`.  
- Wrap components that receive props unchanged with `React.memo`.  
- Keep condition checks **cheap** (avoid heavy computations inside JSX).  
- Avoid creating new objects/arrays inline that cause unnecessary re‑renders.

## 102. What is the purpose of keys in React lists?

## 142. What is React.memo and how does it work?

## 143. What is the useMemo hook and when should you use it?

## 161. What are error boundaries in React?
A component that implements `static getDerivedStateFromError` and/or `componentDidCatch` to catch JavaScript errors in its child tree, log them, and render a fallback UI instead of crashing the whole app.

```jsx

  state = { hasError: false };
  static getDerivedStateFromError() { return { hasError: true }; }
  componentDidCatch(error, info) { logError(error, info); }
  render() {
    return this.state.hasError ? <Fallback /> : this.props.children;
  }
}
```

## 162. How do you implement error boundaries in React?
Create a class component as shown above, wrap parts of the UI with `<ErrorBoundary>`. For functional components, you can use the `react-error-boundary` package which provides a hook‑based API.

## 163. How do error boundaries work with React hooks?
Hooks themselves cannot be error boundaries because they are functions, not components. However, you can place a class‑based error boundary around a component that uses hooks. The boundary will catch errors thrown during rendering, lifecycle, or effects of the child component.

## 164. How do you handle errors in error boundaries?
Inside `componentDidCatch`, log the error (e.g., to an external monitoring service). Optionally, send error details to a server for analysis. Provide a user‑friendly fallback UI that may include a “Retry” button.

## 165. How do you test error boundaries in React?
Render a component that throws an error inside a test, wrap it with the error boundary, and assert that the fallback UI appears.

```jsx
function Bomb() { throw new Error('Boom'); }

render(
  <ErrorBoundary>
    <Bomb />
  </ErrorBoundary>
);
expect(screen.getByText(/something went wrong/i)).toBeInTheDocument();
```

## 166. What are the limitations of error boundaries?
- They **do not catch** errors inside **event handlers**, **asynchronous code**, **server‑side rendering**, or **errors in the error boundary itself**.  
- They only catch errors during **render**, **lifecycle methods**, and **constructor** of child components.

## 167. How do you implement fallback UI with error boundaries?
Return a UI element (e.g., a message, a “Try again” button) when `hasError` state is true.

```jsx
return this.state.hasError ? (
  <div>
    <p>Something went wrong.</p>
    <button onClick={this.retry}>Retry</button>
  </div>
) : this.props.children;
```

## 168. How do you log errors from error boundaries?
Use `componentDidCatch(error, info)` to send details to a logging service (e.g., Sentry, LogRocket).

```jsx
componentDidCatch(error, errorInfo) {
  Sentry.captureException(error, { extra: errorInfo });
}
```

## 169. How do you handle async errors in React?
- Wrap async code in `try/catch`.  
- For promises, use `.catch`.  
- In components, handle errors in `useEffect` by setting error state.  
- Use error boundaries for synchronous render errors; async errors should be handled manually.

## 170. What are the best practices for error handling in React?
- Centralize error handling (e.g., a hook `useError`).  
- Show user‑friendly messages.  
- Log errors to a monitoring service.  
- Provide retry mechanisms where appropriate.  
- Use error boundaries for UI crashes, but handle network/async errors in component logic.

## 171. What are the common React patterns?
- **Higher‑Order Components (HOC)**  
- **Render Props**  
- **Compound Components**  
- **Provider (Context) Pattern**  
- **Controlled vs Uncontrolled Components**  
- **Custom Hooks**  
- **Container/Presentational Separation**  
- **State Reducer Pattern**  

## 172. What is the higher‑order component (HOC) pattern?
An HOC is a function that takes a component and returns a new component with added props or behavior.

```jsx
function greet(name){
    return `Hi!! ${name} `;
}

function greet_name(greeting,message,name){
       console.log(`${greeting(name)} ${message}`);
}

greet_name(greet,'Welcome To GeeksForGeeks','JavaScript');
```

## 173. What is the render prop pattern?
A component receives a function prop that returns JSX, allowing the caller to control rendering.

```jsx
<DataProvider render={data => <List items={data} />} />
```

## 174. What is the compound component pattern?
A parent component manages shared state and renders child components that communicate via context.

```jsx
<Tabs>
  <Tabs.List>
    <Tabs.Tab>One</Tabs.Tab>
    <Tabs.Tab>Two</Tabs.Tab>
  </Tabs.List>
  <Tabs.Panels>
    <Tabs.Panel>Content 1</Tabs.Panel>
    <Tabs.Panel>Content 2</Tabs.Panel>
  </Tabs.Panels>
</Tabs>
```

## 175. What is the provider pattern in React?
Use the Context API to provide a value (state, functions) to a subtree, allowing any descendant to consume it without prop drilling.

```jsx
<ThemeProvider value={theme}>
  <App />
</ThemeProvider>
```

## 176. What is the children prop pattern?
Pass JSX as `children` to a component, enabling flexible composition.

```jsx
<Card>
  <Card.Header>Title</Card.Header>
  <Card.Body>Content</Card.Body>
</Card>
```

## 177. What is the state reducer pattern?
Expose a `state` and `dispatch` from a component (often via context) and let consumers decide how to update state by sending actions, similar to Redux but scoped.

```jsx
const [state, dispatch] = useReducer(reducer, initial);
<Provider value={{ state, dispatch }}>{children}</Provider>
```

## 178. What is the control props pattern?
Pass a prop that controls a component’s internal behavior (e.g., `open` for a modal) and let the parent manage the state.

```jsx
<Modal open={isOpen} onClose={() => setOpen(false)} />
```

## 179. What is the custom hook pattern?
Encapsulate reusable logic (state, effects, subscriptions) into a function that uses built‑in hooks and can be shared across components.

```jsx
function useWindowSize() {
  const [size, setSize] = useState({ width: window.innerWidth, height: window.innerHeight });
  useEffect(() => {
    const onResize = () => setSize({ width: window.innerWidth, height: window.innerHeight });
    window.addEventListener('resize', onResize);
    return () => window.removeEventListener('resize', onResize);
  }, []);
  return size;
}
```

## 180. How do you choose the right React pattern?
- **Complex state sharing** → Context + custom hook or provider pattern.  
- **Cross‑cutting concerns** (auth, logging) → HOC or wrapper component.  
- **Reusable UI logic** → Render props or custom hook.  
- **Component composition** → Compound components or children prop.  
- Consider **readability**, **testability**, and **future scalability**.

## 181. What are the best practices for React development?
- Keep components **small** and **focused**.  
- Prefer **functional components** with hooks.  
- Use **type safety** (TypeScript or PropTypes).  
- Write **unit tests** for logic and **integration tests** for flows.  
- Follow **accessibility** guidelines (ARIA, semantic HTML).  
- Optimize performance (memoization, code splitting).  
- Use **consistent naming** and folder structure.

## 182. How do you structure React applications?
Typical folder layout:

```
src/
 ├─ components/      // reusable UI components
 ├─ pages/           // route‑level components
 ├─ hooks/           // custom hooks
 ├─ context/         // context providers
 ├─ services/        // API calls
 ├─ utils/           // helper functions
 ├─ assets/          // images, fonts
 └─ App.jsx
```

Feature‑based grouping (e.g., `features/auth/`) is also common for larger apps.

## 183. How do you organize React components?
- **Atomic design**: atoms → molecules → organisms → templates → pages.  
- **Feature folders**: each feature contains its own components, styles, tests.  
- Keep **presentational** and **container** components separate when appropriate.

## 184. How do you handle component naming conventions?
- Use **PascalCase** for component filenames and component names (`MyButton.jsx`).  
- Prefix higher‑order components with `with` (`withAuth`).  
- Use descriptive names that convey purpose (`UserList`, `SearchBar`).  
- Avoid generic names like `Component1`.

## 185. How do you manage component dependencies?
- Keep dependencies **explicit** via imports.  
- Use **dependency injection** (props, context) rather than importing globals.  
- For shared utilities, place them in a `utils` folder.  
- Avoid circular dependencies; refactor to separate concerns if they appear.

## 186. How do you handle code reuse in React?
- **Reusable components** with props for configuration.  
- **Custom hooks** for shared logic.  
- **Higher‑order components** for cross‑cutting concerns.  
- **Render props** for flexible UI injection.  
- **Component libraries** (e.g., Material‑UI) for common UI elements.

## 187. How do you implement proper error handling?
- Catch errors in async code and set error state.  
- Use **error boundaries** for UI crashes.  
- Show user‑friendly messages and fallback UI.  
- Log errors to monitoring services.  
- Provide retry mechanisms where feasible.

## 188. How do you optimize React bundle size?
- **Code splitting** (lazy load routes).  
- **Tree shaking**: import only needed functions (`import { debounce } from 'lodash'`).  
- **Remove unused dependencies** (`npm prune`).  
- Use **production build** (`npm run build`).  
- Analyze bundle with **webpack-bundle-analyzer**.

## 189. How do you handle accessibility in React?
- Use **semantic HTML** (`<button>`, `<nav>`).  
- Add appropriate **ARIA attributes** (`aria-label`, `role`).  
- Ensure focus order and keyboard navigation.  
- Provide visible focus outlines.  
- Test with screen readers and accessibility tools (axe, Lighthouse).

## 190. What are the security best practices for React?
- **Escape/encode** any user‑generated HTML (avoid `dangerouslySetInnerHTML`).  
- Use **Content Security Policy** headers.  
- Validate and sanitize inputs on the server.  
- Store tokens securely (httpOnly cookies).  
- Keep dependencies up‑to‑date (`npm audit`).  
- Avoid exposing secrets in client code.

## 191. How do you use TypeScript with React?
- Install `typescript` and `@types/react`, `@types/react-dom`.  
- Rename files to `.tsx`.  
- Define **props** and **state** interfaces or types.

```tsx
interface ButtonProps {
  label: string;
  onClick: () => void;
}
const Button: React.FC<ButtonProps> = ({ label, onClick }) => (
  <button onClick={onClick}>{label}</button>
);
```

## 192. How do you type React props with TypeScript?
Use an interface or type and apply it to the component via `React.FC<Props>` or generic component typing.

```tsx
type CardProps = { title: string; children: ReactNode };
const Card: React.FC<CardProps> = ({ title, children }) => (…);
```

## 193. How do you type React state with TypeScript?
When using `useState`, provide a generic type.

```tsx
const [count, setCount] = useState<number>(0);
```

For complex objects, define an interface.

## 194. How do you type React hooks with TypeScript?
All built‑in hooks are generic. Provide types for state, refs, reducers, etc.

```tsx
const [value, setValue] = useState<string>('');
const inputRef = useRef<HTMLInputElement>(null);
```

## 195. How do you type React events in TypeScript?
Use the appropriate synthetic event type.

```tsx
const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => {
  setValue(e.target.value);
};
```

## 196. How do you type React context with TypeScript?
Create a context with a default value typed.

```tsx
type ThemeContextType = { theme: string; toggle: () => void };
const ThemeContext = React.createContext<ThemeContextType | undefined>(undefined);
```

Consumers use `useContext<ThemeContextType>(ThemeContext)`.

## 197. How do you type React Router with TypeScript?
`react-router-dom` provides types. Use `useParams<{ id: string }>()` and `useNavigate()` with proper generics.

## 198. How do you type Redux with React and TypeScript?
- Define state and action types.  
- Use `configureStore` from Redux Toolkit which infers types.  
- Use `useSelector` with a typed root state.  
- Use `useDispatch<AppDispatch>()`.

## 199. What are the benefits of using TypeScript with React?
- **Compile‑time type safety** reduces runtime bugs.  
- **Better IDE autocomplete** and refactoring.  
- **Self‑documenting code** via interfaces.  
- **Easier onboarding** for new developers.

## 200. What are the challenges of using TypeScript with React?
- **Initial learning curve** for TS concepts.  
- **Verbose typings** for complex props or generics.  
- **Third‑party library typings** may be missing or outdated.  
- **Build configuration** may need extra setup (tsconfig, Babel).
